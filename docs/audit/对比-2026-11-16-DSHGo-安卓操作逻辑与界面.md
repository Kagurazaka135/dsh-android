# 主线 A：安卓专属操作逻辑

## A1 ⭐ 返回键 / 手势导航 / 预测式返回

**它怎么做**：返回键分层全在 Dart 侧：home_shell 的 PopScope 按「快捷面板 → 多选状态 → 抽屉」顺序逐层关闭（home_shell.dart:309-320，canPop 三个条件）；未保存内容由 DiscardGuard 统一拦截（discard_guard.dart:84-91，isDirty 时弹确认）；应用内浏览器 SystemNavigator.pop + PopScope（web_view_page.dart:1020、1057）；16 个页面级 PopScope。**预测式返回未启用**：全仓 `enableOnBackInvokedCallback|predictiveBack` 于 app/android 代码内未见（Manifest/gradle 均无）。原生层无 onBackPressed 覆盖（Flutter 接管）。
**为什么**：无注释直说；PopScope 结构（抽屉优先于退出）是导航壳的常规做法。属「现状做法」。
**我们怎么做**：onBackPressed 四段优先级链：自绘弹窗 → 控制台（页码归零再确认退出）→ WebView canGoBack → 确认退出（MainActivity.java:10601-10616）；mobile.js 无 history/popstate 拦截（grep 未见，侧栏开合由官方前端自管）。
**结论**：不可比（导航栈形态不同：它管自己的路由栈，我们管 WebView 历史栈）。可学的小件是 DiscardGuard 的「脏内容确认」思路——JS 可做（beforeunload 已被 WebView 支持但需测），成本半天。

## A2 ⭐ 键盘 / 输入法避让 / 焦点

**它怎么做**：Manifest `windowSoftInputMode="adjustResize"`（AndroidManifest.xml:70）+ Flutter 侧显式消费 viewInsets：composer 按「可用高度 × 0.4 / 行高」算编辑器行数，clamp(2,6)，且响应字号缩放（composer.dart:145-150）；引导页胶囊在键盘弹出时隐藏（onboarding_scaffold.dart:76，`viewInsets.bottom == 0` 才显示）；宠物输入条与悬浮胶囊都带 `IME_FLAG_NO_EXTRACT_UI`（AskBar.kt:147、OverlayCapsule.kt:257，防横屏键盘全屏化）；甚至为「键盘自动收起」问题建了系统输入法日志采集（SystemImeEvidence.kt、SystemImeLogcat.kt，changelog 1.0.14 #366，白名单事件、不记输入内容）。
**为什么**：composer.dart:146 注释直说「横屏+高字号会把聊天区挤没」；#366 是用户报告的键盘自动收起事故。
**我们怎么做**：Manifest 未声明 windowSoftInputMode（默认 adjustUnspecified，AndroidManifest.xml:56-61 无此属性）；键盘避让全靠 mobile.js：VisualViewport 算键盘高度 → `--kb-height` + 容器 `translateY(-kb)` + rAF 节流（mobile.js:64-99）；防程序化自动聚焦（pointerdown 记录落点，切话题自动 focus 立即 blur，mobile.js:104-156）；v0.4 修复了 transform 导致坐标判定漂移的坑（mobile.js:108 注释）。
**结论**：各有取舍（它是布局重排，我们是视觉平移）。**值得学两条**：①行数随可用高度自适应（JS 可做，半天）；②「输入法诊断采集」方法论——我们的粘贴截断报告（报告-2026-11-12）已经同思路，可把它扩成常设诊断页，1 天。
