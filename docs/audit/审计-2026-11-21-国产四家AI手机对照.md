## 摘要

**四家一句话定位**：小米＝白名单「一步直达」+ 官方亲口承认的 UI 操作学习路线 + 微信 A2A 协议通道（混合）；OPPO＝意图框架声明 + 服务清单路由 + A2A（B 范式倾向最纯）；vivo＝蓝心 Harness 把系统能力统一封装成 6000+ 原子技能（C 倾向，安全架构最完整）；努比亚自有 AI＝Nebula-GUI 纯视觉 VLA 开放泛化（D 的镜像：单一路径但那条路是 GUI 不是 API）。

**三条最重要发现**：
1. **D 范式（模型只有 API 一条路）在四家里零成立**——每家都留了兜底路径或干脆开放泛化；且「被拒后换路径」的行业级实测案例真实存在：微信 A2A 落地本身就是全行业从 GUI 模拟切换到协议通道的事件（旧通道=界面自动化，新通道=应用自己执行）。**但「能力封闭集合」是真趋势**（小米 100 应用/3000 能力、OPPO 40 服务/700 场景、vivo 6000 技能，全是官方计数）——主人的假设一半成立：拦在「做不到」靠的是能力面封闭，不靠拒绝判断；另一半不成立：没有一家敢只给一条路。
2. **代操作的特权底牌实测**（sysapps 观测 + 小米 ROM 一手）：vivo `com.vivo.abe` 持 **DELETE_PACKAGES（卸载应用）+ FORCE_STOP_PACKAGES（强杀进程）+ MOUNT_UNMOUNT_FILESYSTEMS**——观测样本里最凶；小米小爱栈靠 platform 签名拿 `INJECT_EVENTS`（ROM 提取，B 文件 §三）；三星 bixby.wakeup 的 `CAPTURE_AUDIO_HOTWORD+MANAGE_SOUND_TRIGGER` 被 sysapps 观测与本地解包**双向互证**（该库可信度锚点）。
3. **绕过防护在四家的公开材料里均未见**：拒绝计数器、通道切换检测、降级策略——四家官方材料均未见；deny 日志只有 vivo「全链路可信轨迹」最接近。⚠️ **这个结论的边界是「公开材料」**——四家都有云端，服务端是否做了拦截无从观察，不能外推成「行业没有」。

## 二、vivo（重点）

### 2.1 官方宣称的能力

- VDC24（2024-10）PhoneGPT：「蓝心小 V 不仅可以对屏幕界面进行识别和操作，也可以通过接管音频进行自主对话」（官方新闻 vivo.com.cn/brand/news/detail?id=1271）——**早期官方亲口承认屏幕操作路线**。
- VDC26（2026-09-16）蓝心 Harness（官方新闻 id=1389）：「能将 **6000 多项原子技能**转化为智能体可调用的工具，支持超过万种任务」；蓝心智能开放平台支持 Agent/Skill/MCP/原子技能四类接入；OriginOS 7 于 2026-10-09 首批推送（X500 系列首发）。
- 媒体实测（IT之家 X500 实机，ithome.com/1/003/305.htm，可复现操作描述）：聚合订单/短信/收藏生成行程并导入笔记；航班延误定时监控重规划；一句话打车/点咖啡/订票；系统级「查序列号、打开应用」；PC 端「小 V Claw」跨设备检索文档。

### 2.2 「6000+ 原子技能」是什么粒度

- **官方口径**：「把系统、应用、设备能力变成大模型的手和脚」（发布会转述）+「与原系统内核深度融合」——**指向系统/API 层封装**，非 UI 操作录制。
- **第三方类比（线索级）**：知乎专栏称其类似 Claude Code 式 Agent Harness（编排循环+工具调用+记忆管理层）；凤凰网称原子技能是「细粒度的最小能力单元……不可再分的独立技能」（均为第三方分析，不作结论）。
- **文档级实锤：暂缺**。developers.vivo.com 蓝心开放平台文档 JS 渲染抓不到正文（两次尝试，登记缺口）——**粒度问题按任务书要求如实写：官方称 6000+（来源官方新闻稿），未说明是否含 UI 操作封装；现有最硬佐证=IT之家实机行为（打车/点咖啡=服务接入类，查序列号=系统 API 类，混合态）**。
- **判定：C 倾向（系统统一判）**——统一封装、统一调度（Flash/Pro「任务中控」+自研 Agentic 引擎），能力面封闭可数。

### 2.3 固件提取所得

**未获取**。卡点：vivo 官网服务页无新机型公开固件直链（服务→升级页面为产品导航墙，无 X500/X300 固件列表；sysapps 仅 1 台 vivo 设备收录，2026-07-21 同步）。替代证据=sysapps 观测（§七）。

### 2.4 对本项目的启示

- **原子技能封装是「能走 API 的走 API」的行业级答案**——把系统能力拆成不可再分的技能单元给模型调用，而不是让它点屏幕。
- 但 vivo 能这么做的底牌是 `com.vivo.abe` 的签名级权限（DELETE_PACKAGES/FORCE_STOP_PACKAGES/MOUNT_UNMOUNT_FILESYSTEMS——sysapps 观测）——**系统级封装需要系统级权限做底**。本项目无签名：Shizuku 是现有条件下最接近的顶替（能覆盖设置修改/应用管理的大部分原子技能）。
- vivo 的安全架构清单（唯一 Agent ID/最小权限/端侧沙箱/全链路记录）值得整抄进本项目权限设计文档当对照基线。

## 三、OPPO

### 3.1 官方宣称的能力

- ODC24（2024-10，新华网）：发布「全新意图框架」——「通过终端数据与开发者共享意图，对用户实时意图进行判断和推理」。
- ODC26（2026-09-17 官方新闻稿 oppo.com/cn/newsroom/press/549）：一句话直达 **200 项支付宝服务**；一句话发微信消息/拨打电话（A2A）；「小布建议与 40 多家头部三方服务合作，覆盖 700 多个细分场景」「自研蜂群感知技术预判准确率 95%」。
- 小布 Next：端侧 Multi-Agent 集群（技术预览版，招募制）。

### 3.2 技术路线：B 范式倾向最纯

- **意图共享数据结构**（OPPO 开放平台文档 id=13565，JS 渲染抓取不全、据检索摘要转引并已注明）：`IntelligentIntent` 是意图共享的基础数据单元，开发者按模板类型和垂域填数据——**应用声明意图 + 系统消费意图**的 B 范式结构。
- **微信 A2A（2026-06-30 官宣，第二家）**：pconline 报道原文「微信服务端负责执行并返回结果，**全程无需对界面模拟操作**」+ 双重授权 + 关键步骤（发送/支付确认）手动确认 + 同名联系人二次确认——**B 范式 + 敏感操作确认的最完整公开链**。
- **执行层官方未公开**：查了开放平台/ColorOS 官方页/ODC 稿——未见「API 调用还是模拟点击」的技术说明（登记缺口）。
- **判定：B（应用声明+系统/应用执行）**；未见 GUI 兜底官方证据（第三方 36氪 分析称行业 GUI 降为补位——转述级，不作结论）。

### 3.3 固件提取所得

**未获取**。卡点：ColorOS 官网「历史版本下载」页（coloros.com/upgrade/rom，浏览器实测 2026-11-21）**只覆盖 ColorOS 7 及以下**（Find X2 Pro 及更老机型）——新旗舰固件不公开；新机型 OTA 走 PC 助手，分发格式 .ozip 为 OPPO 私有加密容器。sysapps 覆盖：`com.coloros.assistantscreen`（小布界面层：49 权限=4 运行时/2 签名系统级/8 安装时/35 厂商，52.9MB，targetSdk 36，**无 WRITE_SECURE_SETTINGS/INJECT_EVENTS/CAPTURE_AUDIO_HOTWORD**——**印证「界面层不干活」**）+ `com.oplus.aiunit`（91.7MB 引擎体，24 权限，仅 1 条签名级——引擎本身 Manifest 层无杀手权限）。

### 3.4 对本项目的启示

- OPPO 的意图框架=本项目可以**自己定义轻量版**的东西：给自家生态的 App 一份「IntelligentIntent 式声明模板」（能做什么/不能做什么/确认点），不依赖厂商。
- A2A 的「应用自己执行」模式把拒绝权交回应用——与本项目 Guard 的「应用 opt-out」思想同构（AOSP CallerValidator 的 opt-out 分支见 §六）。

### 5.3 范式判定：D 的镜像

- 但它也只有**一条路（GUI）**——不是任务书 D 范式的「只有 API」，而是「只有 GUI」。按任务书判据「被拒后能换路径则 D 不成立」：努比亚自有线没有第二通道可换，从路径单一性看是 D 的镜像形态；从「能力面是否封闭 API 集」看则完全不是 D。**归属标注：D 镜像（单一路径=GUI），非标准 D**。
- ROM 未获取：ztedevices.com 支持页 Z70 Ultra 明示「此产品没有可用的软件」（官方页原文，2026-11-21 实测）；sysapps 未收录努比亚。
- 安全口径：努比亚自有线官方原话未查到（Z70/Z80 稿无安全隐私表述）；豆包款才有「指纹 AI 按键是安全能力的第一道关口」等（归 B3 线）。

## 六、系统层怎么限制模型（任务书 4.5 全量）

### 6.1 Google 五道校验深挖（本地 AOSP 源码逐字核验，五道全部对上）

本地源：`G:\code\ai-phone-audit\aosp\frameworks-base\`（main @ 1cdfff555，主任务 B1 clone）。

| # | 校验 | 验证结果（本轮新挖） |
|---|---|---|
| 1 | `validateCallingPackage` 声明包名=binder UID | 主任务已核（CallerValidatorImpl.java:243-256，SecurityException）✓ |
| 2 | 跨用户需 INTERACT_ACROSS_USERS_FULL | ✓（handleIncomingUser，:198-236） |
| 3 | EXECUTE_APP_FUNCTIONS(_TRUSTED) | ✓ 两权限 protectionLevel 均为 **`internal|role`**（core/res/AndroidManifest.xml:8304、8322——本轮逐字复核） |
| 4 | **opt-out 分支** | ⭐ **静态声明机制实锤**：`AppFunctionStaticMetadataHelper.java:40-41` 定义 `restrictCallersWithExecuteAppFunctions`，属于 **AppFunctionStaticMetadata 静态 schema**（应用经 Jetpack 注解生成、随索引上传进 AppSearch `apps-db`）；`CallerValidatorImpl.java:161-167` 校验时用 `GenericDocument.getPropertyBoolean` 从静态元数据读取。**答案：构建期静态声明，不是运行时设置**。Manifest javadoc 原文：「Apps contributing app functions can opt to disallow callers with this permission, limiting to only callers with EXECUTE_APP_FUNCTIONS_TRUSTED instead」 |
| 5 | 企业策略 | ✓（verifyEnterprisePolicyIsAllowed，:169-180） |

**四家必须回答的两个附加项**：
- **速率限制/调用计数**：grep `rate.?limit|throttle|quota|counter` 于 services/appfunctions/ 全目录 **零命中** → **未见**。
- **审计日志**：**有，但属于遥测而非用户账本**——`AppFunctionsLoggerWrapper`（Wraps AppFunctionsStatsLog）在每次调用后异步写 statsd 原子事件 `APP_FUNCTIONS_REQUEST_REPORTED`（含成功/错误+响应码，AppFunctionsLoggerWrapper.java:56-57；ServiceImpl.java:163-169 调用）。**对照本项目**：docs/权限.md §6.18 想要的「审计账本」是用户可读的留痕——AOSP 的 statsd 是系统遥测，两者不是一回事；但「每次调用必有事件」这个骨架可抄。

### 6.3 ⭐ D 范式结论（任务书 4.7-4：三选一，不悬空）

**结论：D 范式不成立（在国产四家与 Google 的现实产品中）。**

依据（按任务书判据「被拒后能换路径则 D 不成立」，用实测/公开案例而非推理）：
1. **微信 A2A 落地=通道切换的实测级案例**：行业公开承认旧通道=界面模拟、新通道=协议（pconline 原文「全程无需对界面模拟操作」；36氪分析称 GUI 降为补位）——「换路径」不是假设，是 2026 年已发生的行业事件。
2. **Google 官方双轨自认兜底**：AppFunctions（B）与「界面自动化框架」（2026-02 官方博客，主任务 6.1.3）并存——D 的「没有第二条路」被 Google 自己的产品规划否定。
3. 小米官方亲口承认 UI 学习路线（双通道在用）。
4. 努比亚是单一路径但那是 GUI 不是 API——不构成「模型只能调 API」的 D。

**主人的假设哪些部分仍然成立**：**「能力面封闭集合」是真趋势**（三家官方计数白名单）——「能拦在做不到」的第一半（不暴露能力）行业在做；第二半（拒绝后无路可绕）行业没做也不敢做（覆盖面问题，D 范式的代价一节命中：没接入的 App 怎么办——答案=兜底路径，于是 D 不纯）。

### 7.5 观测到的「厂商自加权限」信号

## 附录 B：踩坑记录

1. **官方固件下载页是历史版本墙**：ColorOS 公开下载只到 ColorOS 7（Find X2 Pro 时代）——「官网可下固件」对新旗舰不成立，先看页面覆盖范围再投入。
