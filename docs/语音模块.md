## 二、装完如何验证（按序做）

1. **覆盖安装** APK（同签名；桌面图标不变，数据不丢）。
2. 打开 App → 控制台 → **启动引擎**。
3. 下拉通知栏：应看到常驻通知 **「语音服务就绪」**（另有「引擎保活」一条，共 2 条）。
4. 首次进 App 的权限引导页（或控制台「权限」页）→ **麦克风权限 → 去授权**。
5. 进会话，让 AI 调工具（直接就说话即可）：
   - 「查一下语音状态」→ 应回：TTS 就绪 / 麦克风已授权 / 识别引擎=system
   - 「用语音念：你好，我是小鲸」→ 手机扬声器出声（播报期间调 listen/record 会被半双工闸拒绝，属预期）
   - 「听一下我说什么」→ 说完一句给识别文本（依赖系统语音识别服务）
   - 「录 5 秒音」→ `voice_record`；再「停止录音」→ `voice_record_stop` 返回 WAV 路径
6. **退出界面**（App 关闭）：语音服务继续运行（通知还在）——这是 B 路线的「常驻」形态。
7. **控制台停止引擎**：语音服务一起停止（通知消失）——引擎停了语音桥没人用，不留孤儿服务。

## 三、本次施工修的坑（构建侧，三次翻车记录）

1. **`env.sh` 的 PATH 必须用 `/c/...` 形式**——写 `C:/tmp/...` 时 Git Bash 的 `command -v aapt`
   直接找不到，构建跑到 1/7 报 `aapt: command not found`（`JAVA_BIN` 同因）。已修。
2. **devhome 的 git 是「成品布局」**——主程序在 `payload/bin/git`，`git/` 下只有 libexec+templates；
   上游 build.sh 只认 `git/bin/git` → `cp: cannot stat`，整次构建在 payload 组装末尾 exit 1。已改为两种布局都认。
3. **`rm -rf staging` 偶发 Permission denied**（刚写出的 2.5 万文件正被杀软扫，句柄未释放），
   `set -e` 下整次构建静默死在第 0 步。已加 `clean_dir()`：重试 3 次 + `cmd rd /s /q` 兜底。

另修：`/listen` 的 `lang` 参数原来只认 query、不认 POST body（插件发的 body 参数被静默忽略）。已修。

## 四、v1 时期的 sherpa-onnx 评估记录（历史）

**评估结论（已实证，非猜测）**：
- dsh 内核自带 `dsh-experimental-speech-to-text-sensevoice` **不支持 Android**——其依赖
  `sherpa-onnx-node` 的平台包（optionalDependencies）只有 darwin-arm64/x64、linux-x64/arm64、win-x64/ia32。
  → **A 路线（白嫖内核语音包）在手机上不可行**，B 路线判断正确。
- 官方 Android 支持只有 **sherpa-onnx AAR**（Kotlin + androidx）。两条破法：
  - **(a) 接受 kotlin-stdlib**（只当运行时依赖，不写 Kotlin 源码）——**建议优先**，快；
  - (b) 手写 ~6 个 Java shim 直绑 `.so`（JNI 标准命名约定）——零额外依赖，但签名要对齐、调试贵。
- **模型不进 APK**（SenseVoice int8 约 239MB / KWS zipformer 约 5MB），首启下载到 filesDir 缓存。

**已为集成预留的接口**：
- `VoiceService.sherpaAvailable()`（类探测）/ `handleRecognize()` / `handleWake()`——填实现即可，
  插件侧 `voice_recognize` / `voice_wake` 零改动。
- dsh `speechToText` seam 契约已摸清：实现 `SpeechProvider { info, transcribe({audio, language}, signal) }`
  即可白嫖前端整条链（含准备进度 UI）；`/recognize` 原子接口就是为它预留的宿主侧实现。
