# Codex 磁盘限制 · 施工前置

> 用 Codex（免费额度）跑 dsh-android 施工之前，先把它的盘按住。
> 2026-10-13。**本文只管磁盘，不管代码。**

---

## 0. 一句话

**Codex CLI 有个官方承认的著名 bug：往 `~/.codex/logs_2.sqlite` 打 TRACE 级日志 + SQLite WAL 写放大，实测一台机 21 天写了 ~37TB（年化 ~640TB）——够把一块 1TB 消费 SSD 不到一年写废。**

⚠️ **注意：是 Codex CLI 工具自己的日志行为，不是"那批模型"的锅。** 换模型不解决，得改 Codex 的配置。

---

## 1. 本机现状（不用慌）

`~/.codex`（= `%USERPROFILE%\.codex`）当前 **577M**：

```
logs_2.sqlite  44M    ← 写入放大器（见下）
cache          35M
sessions       31M    ← 对话历史（删除不可逆）
sqlite         24M
visualizations 14M
```

**正常量级。** 网上那些 14.7GB / 54GB / 447GiB 是重度用户 + 老版本。

## 2. ⚠️ 关键区分（决定怎么治）

> **删文件治「空间」，不治「寿命」。**

- **磨损（寿命）** 看**总共写了多少字节** —— 删了也白删，写入早发生了。
- **空间** 看**文件大小** —— 删文件能治。
- 所以 **"文件才 44M" ≠ "没磨损"** —— 那个 bug 伤的是**写入量**，不是文件大小。

**治寿命只有两条路**：① 降日志级别 ② 把日志重定向到内存盘。

---

## 3. 限制措施（按顺序做）

### ① 先确认版本（最省事的一条）

2026-06 官方合了 PR，日志**减少约 85%**。**先用新版**——大概率已经好很多。

```bash
codex --version
```

### ② 关掉遥测镜像

```bash
export OTEL_TRACES_SAMPLER=always_off
```
（Windows 永久设：`setx OTEL_TRACES_SAMPLER always_off`）

### ③ `logs_2.sqlite` 重定向到内存盘（治寿命的硬招）

- **该文件删除安全**（只含诊断，**不含对话**）—— 所以适合丢内存/临时盘。
- **Windows 要装个 RAM disk 工具**（ImDisk / OSFMount / Primo Ramdisk），再把 `~/.codex/logs_2.sqlite`（+ `-wal` / `-shm`）指过去 / 用 `mklink` 软链。
- **没装 RAM disk 的退路**：只能**定期删**（治空间，不治寿命）——
  ```bash
  # 先完全退出 codex（否则句柄占着，删了空间不还）
  rm -f ~/.codex/logs_2.sqlite ~/.codex/logs_2.sqlite-wal ~/.codex/logs_2.sqlite-shm
  ```
  ⚠️ **别删整个 `~/.codex`**，也别删 `state_*.sqlite`、`auth.json`、`config.toml`（这些是状态/认证）。

### ④ `CODEX_HOME` 重定向（便于监控/隔离）

把整个 Codex 家目录指到一个你指定的地方，方便盯大小、也跟别的工具隔离：
```bash
setx CODEX_HOME "G:\code\dsh-android\.codex-home"
```
（可选；不做也行，知道在哪就行。）

### ⑤ 定期清 sessions（治空间）

`sessions` / `archived_sessions` 是**对话历史，删除不可逆**——不是垃圾，谨慎。
现成工具（都默认只读 / dry-run）：
- `npx @betterlmy/codex-cleaner`（`--apply` 才动手，保留最新会话）
- `npx codex-fix`（对超大 logs_2.sqlite）
- cancellAI（brew，Windows 不适用）
