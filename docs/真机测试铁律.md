# 真机测试铁律

> 给所有在这台手机上干活的人 / AI 工人。
> 不是建议，是**验收级别**的判定——违反即任务作废。
> 立此文的起因见 [`事故日志.md`](事故日志.md)。

---

## 唯一前提

**这台手机是主人正在用的东西，不是测试台、不是棋盘、不是沙盒。**

它不是「agent 的工具」，是「主人的东西」。奖励函数分不出这两者，规则必须分。

---

## 三条硬规矩

### 1. 改之前先问

凡是**改动后会在任务结束仍然生效**的东西，动手前先问，不等开工。

| 类别 | 包含 |
|---|---|
| **系统设置** | 屏幕常亮 / 超时、亮度、自动旋转、勿扰、音量、输入法、默认应用、开发者选项、USB 调试、电池优化白名单、时区语言、动画缩放 |
| **持久化软件状态** | 安装 / 卸载 / 停用 / 改默认值 / 登录账号 |
| **别人的数据** | 往真实会话、草稿、剪贴板、聊天记录里写东西 |

**问法就一句**：改哪个键、改成什么、为什么非改不可。

说不清「非改不可」，就不许改。

> ⚠️ 只作用于**本次操作**的指令不算（`input keyevent`、`input tap`、`wm dismiss-keyguard`）。
> 判据是「任务结束后它还生效吗」，不是「它看起来想干什么」。
> `svc power stayon true` 和 `input keyevent KEYCODE_WAKEUP` 在 agent 眼里都是「让它醒着」，
> 但前者改写持久设置，后者只作用于当次。

### 2. 改完必须声明

交付 / 报告 / 回话里**单列一节**「设备状态变更」：

```
| 键 | 原值 | 新值 | 是否已还原 |
|---|---|---|---|
| stay_on_while_plugged_in | 0 | 15 | 是 |
```

没改就写「**无**」。

**只在过程日志里提一句不算声明**——主人不会去翻你的日志。

### 3. 收工必须还原，且贴证据

任务结束前恢复原值，并贴命令输出：

```bash
adb shell settings get global <key>    # 应回到原值
adb shell settings get system <key>
```

**还原不了就先说，别默默收工。**

---

## 四条红线

### 一、「恢复默认」不等于「恢复原状」

主人的原状可能就是非默认值。

**实证**：自动旋转是**故意关着**的（手机稍微一倾斜就翻转，很烦）。看到 `accelerometer_rotation = 0` 就去「帮忙打开」，是第二次冒犯。

**做法**：先读原值，还原到**原值**，不是还原到你觉得合理的样子。

### 二、「改了又改回来」不等于「没发生」

中间那段时间主人在用手机——屏幕在转、锁屏在消失、键盘在换。**损失已经产生。**

**能还原 ≠ 可接受。** 事后还原是保险丝，不是通行证。

### 三、看到开关就拨 = 最严重的一类失误

工具能改的键，**不是「列表里有什么就用什么」**。

模型的错误推理链是：

```
工具列表里有个能改设置的键
  → 任务里出现了变化
  → 「调整环境让它更顺」这个动作被触发
```

它把「我有这个能力」当成了「这个能力现在该用」。

**做法**：动手前必须回答「**这个能力这次用得上吗**」，答不上就不许用。

### 四、开了不算完，关掉才算完

浏览器、被调起来验证的 App、自己起的进程、自己创建的临时文件——**用完关掉 / 清掉**。

任务的完成标准包含「**环境回到你借它之前的样子**」。

---

## 为什么写这么硬

模型侧没有「副作用」这个奖励项，也没有惩罚。

- 乱改设置**不报错**
- 任务照样**完成**
- 没有人**打回重做**

于是它学到的策略是：**为达成目标临时占用一切，中间付出什么都免费。**

这不是「模型不懂事」，是「懂事这件事没有被定义成目标」。训练信号里没有的东西，不会自己长出来。

**所以只能靠规则兜。兜不住，就是主人的手机被莫名其妙地改了，而主人查半天想不到去查设置。**

## 实证（2026-11-12）

| 事故 | 命令 | 后果 |
|---|---|---|
| 锁屏消失 | `svc power stayon true` × 43 次 | `stay_on_while_plugged_in` 被写成 15，插电时屏永不熄灭、锁屏不出现，只剩降亮度 |
| 自动旋转被关 | `android_setting_app` 改 `accelerometer_rotation` | 自动旋转一直关着，主人以为「dsh 和方向锁定有仇」 |

## 排查这类问题的捷径

症状是「**设备行为怪异**」而不是「功能报错」时，**先看系统状态，再看应用**：

```bash
adb shell dumpsys power | grep -iE "mStayOn|mWakefulness"
adb shell settings get global stay_on_while_plugged_in
adb shell settings list global | grep -iE "screen|lock|stay"
adb shell settings list system | grep -iE "screen|rotation|timeout"
```

**把排除项也记下来**。这次 `lockscreen.disabled=0` 和 `screen_off_timeout=30000` 都正常，只有 `stay_on` 一项异常——写下「排除了什么」比只写「问题在哪」更省下一个人的时间。
